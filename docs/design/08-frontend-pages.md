## 0. 怎么用这份清单

**编号**：每个模块一个编号，前缀代表所在页面。

| 前缀 | 页面 / 范围 | 路由 |
| --- | --- | --- |
| G | 全站通用（顶栏、横幅、全局弹窗） | — |
| L | 登录 | 弹窗 + `/login/callback` |
| H | 首页 | `/` |
| T | 交易页 | `/trade/[symbol]` |
| O | 订单历史 | `/orders` |
| B | 排行榜 | `/leaderboard` |
| R | 模拟规则 | `/rules` |

**三处对齐**：Figma 里的 frame / component 用同一个编号命名（如 `T-04 盘口`）；代码骨架里每个模块现在都是一个带编号的占位块（`ModulePlaceholder`）；实现时按编号逐个替换。

**画布尺寸**：桌面优先。主稿 **1440 × 900**，另出一版 **1280 × 800** 验证最窄布局（设计文档定的下限）。第一版不做手机端。

**每个模块要画的状态**（下面各模块不再重复，只列特有状态）：

| 状态 | 说明 |
| --- | --- |
| 正常 | 有数据 |
| 加载中 | 首屏数据还没回来，用骨架屏，不用转圈 |
| 空 | 请求成功但没有数据（没有仓位、没有委托……） |
| 未登录 | 私有数据模块显示"登录后查看" + 登录按钮；行情模块不受影响 |
| 行情降级 | 行情源断开：下单相关按钮禁用，见 G-03 |

**数值展示规则**（全站统一，设计稿请按这个写示例数字）：

- 交易数据用等宽数字（tabular-nums），字体 IBM Plex Sans
- 金额千分位 + 2 位小数：`10,000.00`
- 价格、数量按币对精度：BTCUSDT 价格 1 位（`81,136.6`）、数量 3 位（`0.010`）
- 盈亏、涨跌显式带符号：`+2.34%`、`-1,000.00`
- 算不出来的数（没有标记价时的强平价等）显示 `--`，不显示 `0`
- 颜色：涨 / 买 / 多 `#0ECB81`，跌 / 卖 / 空 `#F6465D`，中性 `#848E9C`，强调 `#F0B90B`

**设计 token**（`packages/ui/src/styles/globals.css`，Figma 出稿后以稿为准回填）：

| token | 值 | 用途 |
| --- | --- | --- |

| `--bg-surface` | `#161A1E` | 卡片、面板 |
| `--bg-elevated` | `#1E2329` | 悬浮层、输入框 |
| `--line` | `#2B3139` | 分割线、边框 |
| `--text-primary` | `#EAECEF` | 正文 |
| `--text-secondary` | `#848E9C` | 次要文字、表头 |
| `--up` / `--down` | `#0ECB81` / `#F6465D` | 涨跌 |
| `--brand` | `#F0B90B` | 主按钮、强调 |
| `--warn-bg` | `#3A2E12` | 降级横幅底色 |

## 1. 全站通用（G）

### G-01 顶栏

| 区域 | 内容 |
| --- | --- |
| 左 | Logo「合约模拟盘」+「模拟交易·虚拟资金」标签 |
| 中 | 主导航：首页 · 交易 · 订单 · 排行榜 · 规则（当前页高亮，按设计稿 2026-09-19） |
| 右 | G-02 连接状态 · G-04 登录入口 / G-05 账户菜单 |

高度 48px，全站固定在顶部。

### G-02 连接状态

小圆点 + 文字：`已连接`（绿）/ `连接中`、`重连中`（黄，闪烁）。指的是浏览器到我们服务端的实时连接，不是币安行情（那个是 G-03）。

### G-03 行情降级横幅

顶栏下方通栏黄条，两种文案：

| 情况 | 文案 |
| --- | --- |
| 服务端刚启动，行情还没连上 | 正在连接币安行情，连上之前暂不能下单。 |
| 行情中断 | 行情连接中断，撮合已暂停。恢复后不会补算中断期间的成交。 |

出现时：下单按钮禁用并改文案（见 T-06），其余页面正常浏览。

### G-04 登录入口

未登录：黄色按钮「登录 / 注册」，点击打开 L-01。
页面刚加载、登录态还在校验时：骨架占位（不要闪一下"登录"按钮再变成账户名）。

### G-05 账户菜单

触发器：头像（显示名首字母）+ 昵称（按设计稿 5:8055）；余额放进点开后的菜单。

下拉内容：

| 项 | 说明 |
| --- | --- |
| 身份行（灰字） | 登录方式 + 标识，如 `EVM 钱包 · 0x12ab…9f3c`、`邮箱 · ab***@gmail.com` |
| 修改昵称 | 打开 G-06 |
| 持仓模式 | 打开 G-07 |
| 重置模拟账户 | 打开 G-08 |
| 退出登录 | 直接退出，不二次确认 |

### G-06 修改昵称弹窗

- 输入框：1～20 个字，不能有控制字符；实时显示字数
- 昵称会显示在排行榜上（提示一句）
- 状态：提交中、服务端报错（输入框下方红字，文案用服务端返回的）

### G-07 持仓模式弹窗

- 单选：单向持仓（默认）/ 双向持仓，每项一句话说明区别
- **锁定状态**：账户还有任何持仓或挂单时不能切换（服务端 `POSITION_MODE_LOCKED`），弹窗里直接说明原因，确认按钮禁用

### G-08 重置模拟账户弹窗

- 说明：撤掉全部挂单、按标记价平掉全部仓位、余额恢复到 10,000 USDT
- 影响：重置后本期不进日榜 / 周榜（排行榜规则）
- 冷却：24 小时一次。冷却中显示"{时间} 之后可以再次重置"，按钮禁用
- 二次确认：危险操作，确认按钮用红色

### G-09 强平通知弹窗

收到强平推送时弹出，**是弹窗不是 Toast**（这是用户最需要理解的一件事，不能一闪而过）。多条强平排队，一条一条确认。

```
⚠ 仓位已被强制平仓

保证金余额 180.00 USDT 已低于维持保证金 200.00 USDT，系统按标记价强制平仓。

仓位                 BTCUSDT 多头 1.000
开仓价 → 强平标记价    50,000.0 → 45,180.7
已实现盈亏           -4,819.28 USDT      （红）
强平清算费           -225.90 USDT        （红）

[ 查看详情 ]  [ 我知道了 ]
```

「查看详情」跳 O-05 强平记录。

### G-10 Toast

右上 / 顶部居中（待设计定）。三种：成功（下单成功、撤单成功）、业务拒绝（服务端中文原因原样显示）、系统异常（带「重试」按钮）。

### G-11 404 / 币对不存在

- 404：「页面不存在」+ 返回首页
- 交易页币对不存在或未开放（T-00）：「XXXUSDT 不存在或未开放交易」+ 去 BTCUSDT

## 2. 登录（L）

### L-01 登录弹窗

标题「登录 / 注册」（按设计稿 5:6852）；底部说明「首次登录自动开户并发放 10,000 USDT；不同登录方式是不同账户」。
三个 tab：**钱包 / 邮箱 / Google**。三种方式各自独立开户（同一个人用不同方式登录会是不同账户，要在界面上说清楚）。

### L-02 钱包登录（tab）

```
1. 点「连接钱包」→ 打开 Reown AppKit 自带的钱包选择弹窗（EVM + Solana 在同一个列表里）
2. 连上后显示：钱包图标 + 地址缩写 + 链
3. 点「签名登录」→ 钱包里弹出签名请求（不花 gas，只是证明地址归属）
4. 成功 → 关闭弹窗
```

需要画的状态：未连接 / 已连接待签名 / 等待钱包签名中 / 用户在钱包里拒绝了签名 / 签名校验失败。
AppKit 弹窗本身不用画，只需要定它的主题色（暗色 + `#F0B90B`）。

### L-03 邮箱验证码登录（tab）

```
1. 输入邮箱 →「发送验证码」
2. 按钮变成 60 秒倒计时「59 秒后重新发送」
3. 输入 6 位验证码（6 个格子或一个输入框，待设计定）→「登录」
```

需要画的状态：邮箱格式错误 / 发送频率限制（60 秒内重复发送）/ 验证码错误（显示剩余次数，5 次后作废）/ 验证码过期。

### L-04 Google 登录（tab + 回跳页）

- tab 内：说明文字 + 按钮「使用 Google 登录」，点击整页跳转到 Google
- 回跳页 `/login/callback`：「正在登录…」→ 成功后回到登录前所在页面
- 失败文案：服务端没配 Google / 校验失败（等太久）/ 用户取消授权 / 服务器出错，都给「返回首页」

## 3. 首页（H）

未登录也能看行情，先让人看到东西再决定要不要登录。

### H-01 产品简介

- 一句话定位：用币安真实实时行情练习 U 本位合约交易，不产生任何真实下单
- 卖点：10,000 USDT 模拟资金 · 真实盘口排队 · 和币安一致的保证金、强平、资金费规则
- 按钮：开始交易（→ `/trade/BTCUSDT`）、登录（未登录时）
- 链接：模拟规则（→ `/rules`，强调"和真实交易所有哪些不同"）
- 数据条（设计稿 2:366）：初始资金 · 最高杠杆（从币对规格算）· 跟踪交易对数 · 20 档真实盘口撮合；不放写死的用户数

### H-02 币对行情列表

列：币对（`BTC/USDT` + 最高杠杆 `150x`）· 最新价 · 24h 涨跌 · 标记价 · 资金费率 · 24h 成交额（缩写，如 `17.10B`，悬停显示精确值）

- 最新价、标记价、资金费率、24h 涨跌、24h 成交额都每秒跳动（缺口 #47 已解决：服务端订币安 `@ticker` 流）；行顺序只在进页面时按成交额排一次，不随推送重排
- 点一行 → 进该币对交易页
- 目前开放 19 个币对，不用分页；可考虑加搜索 / 自选（第一版可不做）

### T-03 K 线图

TradingView Charting Library（公司授权），图表内部 UI（工具栏、指标、周期切换）用库自带的，只调主题色。需要设计的是：

- 图表主题：背景、网格、涨跌色和全站一致
- **图上的线**（这个产品最有用的细节之一，用户不用在表格和图之间来回看）：
  - 开仓均价线：标签 `多 1.000 @ 50,000.0`，可在线上直接平仓
  - 强平价线：红色，标签 `强平 45,180.7`
  - 挂单线：标签 `限价买 0.500 @ 49,000.0`，可拖动改价（第一版可只显示）、可点叉撤单
  - 止盈止损触发线
- 加载中、行情降级时的样子

### T-04 盘口


- 性能要求：每 100ms 刷新，数字不能左右抖（等宽数字）

### T-05 最新成交

三列：价格（按主动买卖着色）· 数量 · 时间（`11:30:05`），最近 50 条，新的在上。

### T-06 下单面板（最复杂，建议单独一页设计稿）

从上到下：

| 区域 | 内容 |
| --- | --- |
| 保证金模式 | 按钮 `全仓` → 打开 T-10 |
| 杠杆 | 按钮 `20x` → 打开 T-09 |
| 开 / 平切换 | **只在双向持仓模式出现**：开仓 / 平仓 |
| 订单类型 | tab：限价 · 市价 · 止盈止损（下拉：止损限价 / 止损市价 / 止盈限价 / 止盈市价） |
| 可用余额 | `可用 9,523.10 USDT`（服务端下发，不在前端算）+ 划转图标（第一版不做划转，可不画） |
| 触发价 | 止盈止损时出现；旁边选触发依据：标记价 / 最新价 |
| 价格 | 限价时出现；右侧「最新」快捷按钮；步进按钮按 tickSize；偏离标记价 ±5% 时输入框下方黄色警告 |

| 预估区（买、卖各一列） | 成本 `2,495.00 USDT` · 可开最大 `1.234 BTC` · 预估强平价 `45,180.7`（慢半拍出现，见第 9 节） |
| 下单按钮 | 绿「买入 / 做多」+ 红「卖出 / 做空」并排 |

**下单按钮的状态**（都要画）：

| 状态 | 按钮 |
| --- | --- |
| 未登录 | 一个黄色按钮「登录」 |
| 行情降级 | 禁用，「行情中断，暂停交易」 |
| 输入校验不通过 | 禁用，按钮上或输入框下写具体原因（如「数量低于最小下单量 0.001」） |
| 提交中 | 禁用 + loading，防重复提交 |
| 正常 | 绿 / 红 |

**输入框的校验提示**（前端即时反馈，服务端还会再校验一遍）：价格不是 tickSize 整数倍（失焦时自动吸附）、数量不是 stepSize 整数倍、低于最小数量、名义价值低于最小下单额、价格偏离过大（黄色警告，不拦）。
