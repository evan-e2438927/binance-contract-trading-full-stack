# 01 · 合约业务基础

> 这份文档不讲代码，讲**业务规则本身**。
> 目标是：读完后能看懂 `04-backend-design.md` 里的每一个公式。
> 全文只讨论**币安 U 本位永续合约**，计价和保证金资产都是 USDT。

---

## 一、合约到底是什么

现货是一手交钱一手交货：你花 50,000 USDT，真的拿到 1 个 BTC。

合约不交货。它更像**和交易所签一张赌价格的合同**：你说"我看涨 1 个 BTC 的量"，交易所不要你付 50,000，只要你压一笔**保证金**在那儿。价格涨了，差价归你；跌了，从保证金里扣。扣到保证金不够兜底，交易所就强行把合同作废——这叫**强平（爆仓）**。

"永续"是说这张合同**没有到期日**。但没有到期日就有个新问题：合约价格凭什么跟着现货走？答案是**资金费**——定期在多空之间互相转账，把合约价格往现货价格上拽（第八节细说）。

所以合约交易里真正要盯的只有三件事：

1. 我压了多少保证金
2. 现在浮亏多少
3. 还差多少就被强平

下面所有概念，都是为了把这三句话算准。

---

## 二、名义价值、杠杆、保证金

### 名义价值

你这张合同管着多少钱的货。

```
名义价值 = 持仓数量 × 价格
```

1 BTC 的多单，价格 50,000 → 名义价值 50,000 USDT。

**注意：算不同的东西用的价格不一样**，这是最容易错的地方。

| 场景 | 用哪个价 |
| --- | --- |
| 下单时算需要多少保证金 | 委托价（市价单用盘口估算） |
| 算未实现盈亏 | **标记价格** |
| 算维持保证金、判断强平 | **标记价格** |
| 算资金费 | **标记价格** |

### 杠杆与起始保证金

杠杆就是"名义价值是保证金的几倍"。

```
起始保证金（IM） = 名义价值 ÷ 杠杆
```

50,000 的名义价值，10 倍杠杆 → 压 **5,000 USDT**。

换个说法：**杠杆不是借钱，是决定你要押多少**。押得少（高杠杆），价格稍微反向走一点就吃光押金；押得多（低杠杆），扛得住的波动就大。

10 倍杠杆意味着：价格反向走约 10%，押金就没了。

### 四种"余额"必须分清

币安界面上这四个词都出现，含义完全不同：

| 名词 | 含义 |
| --- | --- |
| **钱包余额** | 已经结算落袋的钱。只有平仓、手续费、资金费才会改它 |
| **未实现盈亏** | 手上仓位现在浮盈浮亏多少，按标记价算，随时变 |
| **保证金余额** | = 钱包余额 + 未实现盈亏。**判断会不会爆仓看这个** |
| **可用余额** | = 保证金余额 − 已占用保证金 − 挂单冻结。能拿来开新仓的钱 |

常见误会：浮亏了钱包余额不会变。真正在缩水的是**保证金余额**。

## 三、标记价格：为什么不用最新成交价

合约页上有两个价：**最新价格**（最近一笔成交）和**标记价格**。

盈亏和强平**只认标记价格**。

原因很实在：最新价格是可以被人为砸出来的。有人在薄的盘口砸一笔大单，价格瞬间插到很低再弹回来（俗称"插针"）。如果强平按最新价走，一大批人就在那零点几秒里被平掉了。

标记价格是币安根据**多家现货交易所的指数价格**，叠加一个平滑过的基差算出来的，不会被单一交易所的一笔大单带偏。

**对本系统的意义**：我们不自己算标记价格，直接订阅币安 `<symbol>@markPrice@1s` 推送的值。图表和最新成交展示用最新价，**一切盈亏和风控计算用标记价**。

## 四、未实现盈亏与开仓均价

```
多头 未实现盈亏 = (标记价格 − 开仓均价) × 持仓数量
空头 未实现盈亏 = (开仓均价 − 标记价格) × 持仓数量
```

**回报率（ROE）**是浮盈相对你押的保证金，不是相对名义价值：

```
ROE = 未实现盈亏 ÷ 起始保证金
```

10 倍杠杆下价格涨 1%，ROE 显示 +10%。界面上那个吓人的百分比就是这么来的。

### 均价怎么变

同方向加仓，均价按数量加权：

```
新均价 = (旧均价 × 旧数量 + 成交价 × 新增数量) ÷ (旧数量 + 新增数量)
```

**算例**：已有 1 BTC 多单 @ 50,000，再买 1 BTC @ 52,000 → 新均价 `(50,000 + 52,000) ÷ 2 = 51,000`

**减仓不改均价**，只把那部分浮盈变成已实现盈亏进钱包：

```
平仓已实现盈亏（多头） = (平仓价 − 开仓均价) × 平仓数量
```

**算例**：2 BTC 多单 @ 51,000，卖 1 BTC @ 53,000 → 已实现 `(53,000 − 51,000) × 1 = +2,000`，剩 1 BTC 均价仍是 51,000。

## 五、维持保证金与杠杆分层

### 维持保证金（MM）

保底线。保证金余额掉到这条线以下，就强平。

它**不是固定比例**，而是随仓位大小分层递增。逻辑很直白：仓位越大，交易所要接盘越难，要求你留的底线越厚。

币安用一张**分层表**，每层三个数：名义价值上限、维持保证金率（MMR）、**速算额（cum）**。

```
维持保证金 = 名义价值 × 该层 MMR − 该层速算额
```

速算额是干嘛的？**它保证跨层时 MM 是连续的**，不会在边界上突然跳一截。

### BTCUSDT 分层表（示例，上线前须以币安实际值为准）

| 层 | 名义价值区间(USDT) | 最大杠杆 | MMR | 速算额 |
| --- | --- | --- | --- | --- |
| 1 | 0 – 50,000 | 125x | 0.40% | 0 |
| 2 | 50,000 – 600,000 | 100x | 0.50% | 50 |
| 3 | 600,000 – 3,000,000 | 50x | 1.00% | 3,050 |
| 4 | 3,000,000 – 12,000,000 | 20x | 2.50% | 48,050 |
| 5 | 12,000,000 – 70,000,000 | 10x | 5.00% | 348,050 |
| 6 | 70,000,000 – 100,000,000 | 5x | 10.00% | 3,848,050 |
| 7 | 100,000,000 – 230,000,000 | 4x | 12.50% | 6,348,050 |
| 8 | 230,000,000 – 480,000,000 | 3x | 15.00% | 12,098,050 |
| 9 | 480,000,000 – 600,000,000 | 2x | 25.00% | 60,098,050 |
| 10 | 600,000,000 – 800,000,000 | 1x | 50.00% | 210,098,050 |

**验证连续性**（这也是种子脚本要自动校验的）：

名义价值正好 50,000 时——
- 按第 1 层：`50,000 × 0.40% − 0 = 200`
- 按第 2 层：`50,000 × 0.50% − 50 = 200` ✓

名义价值正好 600,000 时——
- 按第 2 层：`600,000 × 0.50% − 50 = 2,950`
- 按第 3 层：`600,000 × 1.00% − 3,050 = 2,950` ✓

> ⚠️ **上面这张是教学示例，不是币安现行数值**（现行 BTCUSDT 第 1 层上限已是 300,000、150x）。
> 真实分层表来自官方签名接口 `GET /fapi/v1/leverageBracket`：server 用只读 API Key 每天 UTC 00:05 同步进数据库，
> 写库前校验结构与连续性，写库后读回核对，变化留快照。详见 `03-database-design.md` 的 `leverage_brackets` 一节。
>
> 历史：最初因为"不用 API Key"定为人工维护、季度复核；2026-09-16 改为官方接口同步。

### 分层还限制最大杠杆

表里"最大杠杆"那列是有效的。仓位名义价值涨到第 3 层，最大只能用 50 倍。

币安的做法是**自动降杠杆**并追加保证金要求。**我们的做法是下单前校验，跨到不允许当前杠杆的层就直接拒单**，提示"当前杠杆下最大可开 X"。理由：自动降杠杆会悄悄改变用户的强平价，模拟盘里这种背着用户动手的行为比拒单更糟。

> **更正（2026-09-17 核对币安文档）**：上面"币安自动降杠杆"的说法不准确。币安下单时同样直接拒单，错误码 `-2027 MAX_LEVERAGE_RATIO`（"Exceeded the maximum allowable position at current leverage."），并不会自动降杠杆。所以我们的拒单做法本身就和币安一致。

## 六、强平：什么时候爆，爆在哪个价

### 保证金率

界面右上角那个百分比：

```
保证金率 = 维持保证金总额 ÷ 保证金余额
```

达到 **100%** 强平。

### 强平价格

反过来问："价格走到哪，保证金率正好到 100%？"那个价就是**强平价**。

币安通用公式（我们直接采用）：

```
                WB − TMM₁ + UPNL₁ + cumB − cumL − Side₁ × Pos₁ × EP₁
强平价 = ─────────────────────────────────────────────────────────────
                        Pos₁ × MMR₁ − Side₁ × Pos₁
```

| 符号 | 含义 |
| --- | --- |
| WB | 钱包余额（逐仓时 = 该仓位的逐仓保证金） |
| TMM₁ | **除本仓位外**其余仓位的维持保证金之和 |
| UPNL₁ | **除本仓位外**其余仓位的未实现盈亏之和 |
| cumB | 逐仓仓位的速算额 |
| cumL | 全仓仓位的速算额 |
| Side₁ | 多头 = 1，空头 = −1 |
| Pos₁ | 本仓位数量（绝对值） |
| EP₁ | 本仓位开仓均价 |
| MMR₁ | 本仓位所在层的维持保证金率 |

看着吓人，但**单仓位**时会塌缩成很简单的式子。

### 算例 A · 逐仓多头

BTCUSDT 逐仓开多，开仓价 50,000，数量 1 BTC，10 倍杠杆。
→ 名义价值 50,000，逐仓保证金 WB = 5,000，第 1 层：MMR = 0.4%，cum = 0。
→ 只有这一个仓位，所以 TMM₁ = 0、UPNL₁ = 0、cumL = 0。

```
强平价 = (5,000 − 1 × 1 × 50,000) ÷ (1 × 0.004 − 1 × 1)
       = −45,000 ÷ −0.996
       = 45,180.72
```

**反向验算**（写测试就这么验）：价格跌到 45,180.72——

- 浮亏 = 50,000 − 45,180.72 = 4,819.28
- 保证金余额 = 5,000 − 4,819.28 = **180.72**
- 维持保证金 = 45,180.72 × 0.4% = **180.72** ✓

两数相等，保证金率正好 100%。

### 算例 B · 逐仓空头

同样的仓位，方向换成空（Side = −1）：

```
强平价 = (5,000 + 1 × 1 × 50,000) ÷ (1 × 0.004 + 1 × 1)
       = 55,000 ÷ 1.004
       = 54,780.88
```

验算：涨到 54,780.88，空头浮亏 4,780.88，保证金余额 219.12；维持保证金 = 54,780.88 × 0.4% = 219.12 ✓

> **注意（设计缺口 #24，第 07 讲发现）**：这个算例为了演示公式固定用了第 1 层（0.4%）。但 54,780.88 的名义价值已经超过第 1 层上限 50,000，按分层表应该用第 2 层（mmr 0.5%、cum 50）：强平价 = (5,000 + 50,000 + 50) ÷ (1 + 0.005) = **54,776.12**。引擎的风控扫描按名义价值查层，实际在 54,776.12 强平。公式本身没错，错的是选层。

### 算例 C · 全仓多头（只有这一个仓位）

钱包余额 10,000，其余同算例 A：

```
强平价 = (10,000 − 50,000) ÷ (0.004 − 1) = −40,000 ÷ −0.996 = 40,160.64
```

验算：跌到 40,160.64，浮亏 9,839.36，保证金余额 160.64；维持保证金 = 40,160.64 × 0.4% = 160.64 ✓

**对比 A 和 C**：同样的仓位，全仓的强平价（40,160）比逐仓（45,180）低得多——因为全仓拿整个账户的 10,000 兜底，逐仓只有 5,000。代价是**爆仓时全仓赔掉整个账户，逐仓只赔那 5,000**。这就是两种模式的全部区别。

## 七、全仓 vs 逐仓

| | 逐仓（Isolated） | 全仓（Cross） |
| --- | --- | --- |
| 保证金来源 | 只有分配给这个仓位的那笔钱 | 整个账户的钱包余额 |
| 爆仓损失上限 | 就是那笔逐仓保证金 | **整个账户余额** |
| 多仓位互相影响 | 不影响，各爆各的 | 互相影响：A 仓浮盈能给 B 仓续命 |
| 强平价 | 开仓后基本固定 | **随其他仓位盈亏一直在变** |
| 适合 | 严格控制单笔损失 | 多仓位共享资金效率 |

这就是为什么公式里有 TMM₁ 和 UPNL₁ 两项——**全仓下别的仓位的状态会挪动这个仓位的强平价**。逐仓时这两项是 0，公式才塌缩得那么干净。

### 全仓的强平判定

全仓不逐个仓位判，而是**整个账户一起判**：

```
当  保证金余额 ≤ 所有全仓仓位的维持保证金之和  →  触发强平
```

本系统的处理：触发后把该账户所有全仓仓位按标记价一次性全平。币安真实逻辑是逐步减仓 + 保险基金接管，我们不做那一层。

## 八、资金费

### 它解决什么问题

永续合约没有到期日，没有"到期按现货价交割"这个锚。合约价格凭什么不跑偏？

靠资金费：每 8 小时，多空之间互相转一笔钱。

- 合约价 **高于**现货 → 费率为正 → **多头付给空头** → 做多变贵，压住价格
- 合约价 **低于**现货 → 费率为负 → **空头付给多头** → 做空变贵，抬起价格

纯粹的经济学杠杆：不强制任何人做什么，只让偏离的一方持续付钱。

### 怎么算

```
资金费 = 仓位名义价值（按标记价） × 资金费率
```

结算时间：**UTC 00:00 / 08:00 / 16:00**（北京时间 08:00 / 16:00 / 24:00）。

只有在**结算那一刻持仓**才付/收。07:59 平掉，一分钱不付。

**算例**：1 BTC 多单，结算时标记价 50,000，费率 +0.01%

```
资金费 = 50,000 × 0.0001 = 5 USDT   （你付出 5 USDT）
```

资金费**直接扣钱包余额**，和盈亏、手续费一样是真实现金流。高杠杆长期持仓时，这笔钱会慢慢啃掉本金。

**一个必须处理的边界**：扣完资金费如果导致保证金率 ≥ 100%，要**立刻触发强平检查**。这在真实交易里经常发生。

## 九、手续费

| 角色 | 什么情况 | 费率 |
| --- | --- | --- |
| **Maker**（挂单方） | 限价单挂进盘口等着被吃 | 0.02% |
| **Taker**（吃单方） | 立刻和对手方成交（市价单、或穿透盘口的限价单） | 0.05% |

```
手续费 = 成交名义价值 × 费率
```

市价开仓 1 BTC @ 50,000：`50,000 × 0.05% = 25 USDT`

一开一平两次 Taker 就是 50 USDT。10 倍杠杆下相当于押金的 1%——**光手续费就要价格走对 0.1% 才能打平**。高频交易会被这个数字吃掉。

## 十、双向持仓

| 模式 | 说明 |
| --- | --- |
| **单向持仓** | 一个币对只能有一个方向的仓位。持多时下空单 = 减仓/反手 |
| **双向持仓** | 同一币对可**同时**持多头和空头仓位，各自独立算均价和盈亏 |

双向持仓下，下单必须额外指定 `positionSide`：`LONG` / `SHORT`。单向持仓下是 `BOTH`。

**对应关系**（下单参数最容易错的地方，记牢）：

| 意图 | side | positionSide |
| --- | --- | --- |
| 开多 / 加多 | BUY | LONG |
| 平多 / 减多 | SELL | LONG |
| 开空 / 加空 | SELL | SHORT |
| 平空 / 减空 | BUY | SHORT |

**切换模式的前提**：必须无持仓、无挂单。

### 反手只存在于单向模式

单向模式下，2 BTC 多单，一张 3 BTC 卖单成交：

```
第 1 步：平掉 2 BTC，结算已实现盈亏
第 2 步：剩余 1 BTC 以成交价开一个新的空头仓位
```

双向模式下不存在反手——卖出 LONG 仓位超出部分会被拒，或者必须显式下 SHORT 单。这是双向模式更安全的地方。

## 十一、订单类型与有效方式

### 订单类型

| 类型 | 说明 |
| --- | --- |
| `LIMIT` | 限价单，指定价格挂着等成交 |
| `MARKET` | 市价单，立刻按对手方盘口逐档吃 |
| `STOP` | 止损限价。标记价触及触发价后，挂出一张限价单 |
| `STOP_MARKET` | 止损市价。触发后直接市价成交 |
| `TAKE_PROFIT` | 止盈限价 |
| `TAKE_PROFIT_MARKET` | 止盈市价 |

止损和止盈的区别只在触发方向：**止损是"往亏的方向走到某点就认输"，止盈是"往赚的方向走到某点就落袋"**。

### 有效方式（TIF）

| TIF | 含义 |
| --- | --- |
| `GTC` | 一直挂着直到成交或撤单（默认） |
| `IOC` | 立刻成交能成的部分，剩下的撤掉 |
| `FOK` | 要么全部立刻成交，否则整单撤掉 |
| `GTX` | 只做 Maker。如果会立刻成交，直接撤掉 |

### 两个开关

- **只减仓（reduceOnly）**：只能减少仓位，绝不反向开仓。仓位平完后残余的只减仓单自动撤销。
- **全部平仓（closePosition）**：触发单专用，触发时按当前全部仓位数量平掉。

## 十二、一笔完整交易的资金流水

把上面所有东西串起来。账户初始 10,000 USDT：

| 步骤 | 动作 | 资金变化 | 钱包余额 |
| --- | --- | --- | --- |
| 1 | 市价开多 1 BTC @ 50,000，10x，逐仓 | 划 5,000 做逐仓保证金；付 Taker 费 25 | **9,975** |
| 2 | 价格涨到 51,000 | 浮盈 +1,000（**不进钱包**） | 9,975（保证金余额 10,975） |
| 3 | UTC 16:00 结算，费率 +0.01%，标记价 51,000 | 付资金费 51,000 × 0.0001 = 5.1 | **9,969.9** |
| 4 | 限价 52,000 平多，成交（Maker） | 已实现 +2,000；付 Maker 费 52,000 × 0.02% = 10.4 | **11,959.5** |

净收益 **+1,959.5 USDT**，ROE = 1,959.5 ÷ 5,000 = **+39.19%**。

摩擦成本：手续费 35.4 + 资金费 5.1 = **40.5 USDT**。价格走对了 4%，摩擦占掉约 2% 的收益。

**这张表就是 `ledger`（资金流水）表要记录的东西，一行不能少。**

## 十三、术语速查

| 中文 | 英文 | 一句话 |
| --- | --- | --- |
| 名义价值 | Notional Value | 数量 × 价格 |
| 起始保证金 | Initial Margin | 名义价值 ÷ 杠杆 |
| 维持保证金 | Maintenance Margin | 保底线，名义价值 × MMR − 速算额 |
| 维持保证金率 | MMR | 分层表里的比例 |
| 速算额 | cum / maintAmount | 让跨层时 MM 连续的修正项 |
| 钱包余额 | Wallet Balance | 已结算落袋的钱 |
| 保证金余额 | Margin Balance | 钱包余额 + 未实现盈亏，**判断爆仓看这个** |
| 可用余额 | Available Balance | 还能拿去开仓的钱 |
| 保证金率 | Margin Ratio | 维持保证金 ÷ 保证金余额，到 100% 强平 |
| 标记价格 | Mark Price | 抗插针的价格，盈亏和强平都用它 |
| 最新价格 | Last Price | 最近一笔成交价，只用来展示 |
| 指数价格 | Index Price | 多家现货加权，标记价的基础 |
| 未实现盈亏 | Unrealized PnL | 浮盈浮亏 |
| 已实现盈亏 | Realized PnL | 平仓落袋的盈亏 |
| 强平价 | Liquidation Price | 保证金率到 100% 的那个价 |
| 资金费 | Funding Fee | 每 8 小时多空互转的钱 |
| 挂单方 / 吃单方 | Maker / Taker | 提供流动性 / 消耗流动性 |
| 只减仓 | Reduce Only | 这单只能减仓 |
| 双向持仓 | Hedge Mode | 同币对可同时持多和持空 |
