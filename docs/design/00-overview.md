# 00 · 项目总览

---

## 一、这是个什么系统

用**币安的真实实时行情**，跑一套**我们自己实现**的账户、撮合、风控、清算逻辑，让任何人连上钱包就能用虚拟 USDT 练合约。

三个词各自的含义：

| 词 | 含义 |
| --- | --- |
| **实时** | 行情是币安的真行情，WebSocket 推过来。不是回放，不是随机数 |
| **模拟** | 钱是假的。USDT 由我们的服务发放和记账，**不产生任何真实下单**。唯一的币安 API Key 是只读 Key，只在服务端同步杠杆分层表 |
| **复刻** | 杠杆分层、维持保证金、标记价格、资金费、强平、双向持仓——币安上真实存在的机制，第一版就要有 |

### 为什么不是又一个玩具模拟盘

市面上的模拟盘通常把机制简化掉：没有杠杆分层，维持保证金是个固定比例，资金费不存在，强平就是"价格到了就平"。这样练出来的手感是假的——用户以为自己学会了，上真实盘第一天就被现实教育。

这个系统的目标是**机制上真实**。代价是工程量大得多，但这正是它值得做的原因。

## 二、第一版边界

### 做

| 范畴 | 内容 |
| --- | --- |
| 合约类型 | USDT 本位永续合约 |
| 交易对 | 20 个主流币对，配置化，加币对不改代码 |
| 持仓模式 | 单向持仓 + 双向持仓（对冲模式） |
| 保证金模式 | 全仓 + 逐仓 |
| 订单类型 | 限价、市价、STOP、STOP_MARKET、TAKE_PROFIT、TAKE_PROFIT_MARKET |
| 订单选项 | GTC / IOC / FOK / GTX、只减仓、全部平仓 |
| 风控 | 杠杆分层维持保证金、保证金率、强平价、自动强平 |
| 资金费 | 币安真实费率，每 8 小时结算 |
| 账户 | 钱包 / 邮箱验证码 / Google 三种方式登录开户，发放模拟 USDT、可重置、资金流水、权益曲线、排行榜 |
| 端 | 仅 Web，桌面为主 |

### 不做

| 不做 | 原因 |
| --- | --- |
| USDC 本位、币本位合约 | 计价资产不同，保证金和盈亏是另一套公式 |
| 历史回测 / 加速回放 | 定位是"实时"。引擎设计要预留，但不实现 |
| 保险基金 + ADL 自动减仓 | 要模拟对手方仓位分布，工程量翻倍 |
| 跟踪止损、冰山单、TWAP | 使用率低，撮合复杂度高 |
| VIP 费率档、BNB 折扣 | 固定标准档，配置化留口子 |
| 移动端（apps/native） | Expo 目录先不动 |
| 多语言 | 只做中文；主题只做暗色 |
| 跨身份账户合并 | 一个登录身份（钱包地址 / 邮箱 / Google）= 一个独立账户，不做绑定合并 |

## 三、技术决策定稿

后面所有设计文档都是这张表的展开。代码里如果和它冲突，以它为准。

### 行情

| 决策点 | 定稿 | 理由 |
| --- | --- | --- |
| 交易对范围 | 20 个主流币对 | 每个币对要维护盘口 + 标记价 + 资金费，全量 500 个扛不住也调不完 |
| 行情由谁拿 | **服务端统一订阅，再转发给前端** | 撮合引擎本来就要在服务端维护盘口；前端再连一遍等于两份数据，会出现"页面显示成交了但我的单没成交" |
| 深度档位 | `depth20@100ms` 有限档快照 | 20 档对撮合足够；全量增量要处理 out-of-sync 和快照对齐，收益不成正比 |
| K 线 | 直接订阅币安 kline 流 + REST 拉历史 | 自己从成交聚合一定和币安图对不上 |
| 图表库 | lightweight-charts | 免费、体积小；TradingView Charting Library 要商用授权 |
| 部署区域 | 可直连币安的海外区域 | `fapi.binance.com` 国内机器基本连不上 |

### 撮合

| 决策点 | 定稿 | 理由 |
| --- | --- | --- |
| 限价单成交判定 | **拟真排队**：记录前方挂单量，用真实成交量逐步消耗 | "价格穿透才成交"两行代码就能写，但一挂单就知道是假的 |
| 市价单成交 | 按对手方盘口**逐档吃**，产生滑点和均价 | 一口价学不到"大单冲击成本" |
| 吃穿 20 档 | **拒单**，不编价格 | 滑点惩罚系数是拍脑袋的，用户一研究就露馅 |
| 撮合触发 | 行情事件驱动 | 定时轮询会漏掉两次 tick 之间的价格穿透 |
| 手续费 | Maker 0.02% / Taker 0.05% 固定 | 标准档够用 |
| 数值精度 | **全程 bigint 整数定标（1e8）** | 浮点误差会让强平价差几分钱，用户截图说"我没爆"时没法解释 |

### 风控

| 决策点 | 定稿 | 理由 |
| --- | --- | --- |
| 保证金模式 | 全仓 + 逐仓都做 | "完整复刻"的一部分；逐仓强平比全仓简单，一起做边际成本低 |
| 杠杆分层表 | **server 每日用官方签名接口同步**（只读 Key），写库前后双重校验，变更留快照 | 手抄易错且滞后；常驻服务不依赖未公开的网页接口。2026-09-16 前曾用人工维护 / 网页 bapi，已废弃 |
| 强平 | 标记价触及强平价 → 撤单 → 强平单吃盘口、吃不完按破产价平 + 按币对清算费（BTC 1.25%）（第 07 讲按币安改） | 不做保险基金/ADL |
| 标记价格 | 直接用币安 `markPrice` 流 | 自己算一定有偏差，而强平完全按它走 |
| 资金费 | 币安实际费率，UTC 00:00 / 08:00 / 16:00 结算 | 与真实一致 |
| 跨层杠杆超限 | **拒单**，不自动降杠杆 | 自动降杠杆会悄悄改用户的强平价，比拒单更糟。（2026-09-17 核对：币安下单时同样直接拒单，错误码 `-2027 MAX_LEVERAGE_RATIO`（"Exceeded the maximum allowable position at current leverage."），并不会自动降杠杆，这一条和币安一致） |

### 账户与登录

| 决策点 | 定稿 |
| --- | --- |
| 初始模拟金 | 10,000 USDT，可重置，冷却 24 小时 |
| 账户唯一性 | 一个登录身份（钱包地址 / 邮箱 / Google）= 一个独立账户，不做绑定合并 |
| 排行榜 | 做，需要每日权益快照表 |
| 钱包登录 | 自己实现 SIWE（EVM）/ SIWS（Solana）验签，不引第三方托管 |
| 邮箱登录 | 6 位数字验证码，服务端发信、服务端校验，不用 magic link |
| Google 登录 | OAuth2 Authorization Code + PKCE，用轻量客户端库 `arctic` 自己接，不引入完整认证框架 |
| 三种方式的关系 | 互相独立，不做账户合并；"不引第三方托管"针对的是**资产托管**，OAuth 在这里只做身份验证，不冲突 |
| 会话 | 服务端自签 JWT，7 天，三种登录方式共用同一套签发/校验逻辑 |

### 部署与运行

| 决策点 | 定稿 | 理由 |
| --- | --- | --- |
| 拓扑 | web 留 Cloudflare Workers；**server 独立部署到 VPS** | 常驻撮合引擎 + 长连接 WS 在 Workers 上跑不了 |
| 引擎状态 | 纯内存 + 定期/事件落 Postgres，单实例，不引 Redis | 单实例内存态最简单，重启可从库恢复 |
| 数据归档 | 成交/流水按月分区，90 天以上归档 | Supabase 写入量不是无限的 |

## 四、技术栈

沿用已有的 Better-T-Stack 脚手架：

```
binance-contract-trading-full-stack/
├── apps/
│   ├── web/        Next.js 16 + React 19 + Tailwind 4 + shadcn/ui   → Cloudflare
│   ├── server/     Hono + @hono/node-server（常驻 Node 进程）        → VPS
│   └── native/     Expo（本版不动）
└── packages/
    ├── shared/     ★新增：类型、枚举、错误码、定标换算
    ├── engine/     ★新增：撮合/风控纯逻辑内核
    ├── ui/         共享 shadcn 组件
    ├── db/         Drizzle schema + migrations                       → Supabase Postgres
    ├── config/     共享 tsconfig / lint
    └── infra/      Alchemy 部署（只管 web）
```

`packages/shared` 和 `packages/engine` 是本项目要新建的两个包，作用见 `02-architecture.md`。

## 五、里程碑

| 阶段 | 内容 | 验收标准（能看见的事） |
| --- | --- | --- |
| **M0 地基** | 定标库；引擎骨架；数据库 schema 与种子 | `seed:symbols` + `sync:brackets` 后 20 个币对的规格和分层表已在库里，`verify:brackets` 与官方 0 差异 |
| **M1 行情** | 币安 WS 接入；盘口/标记价/K 线；前端图表与盘口 | 页面和币安官网同步跳动，断网 30 秒后自动恢复 |
| **M2 账户** | 钱包验签 / 邮箱验证码 / Google 三种登录统一发 JWT；开户发钱；私有推送 | MetaMask、Phantom、邮箱验证码、Google 都能登录，刷新不掉线，余额 10000 |
| **M3 撮合** | 限价/市价；拟真排队；开平仓；双向持仓；全仓/逐仓 | 挂单能看到排队量并按规则成交；市价单有滑点；仓位数字和手算一致 |
| **M4 风控** | 杠杆分层；保证金率；强平；资金费 | 触及强平价即平；整点能看到资金费流水 |
| **M5 进阶单** | 四类触发单；只减仓；调杠杆与保证金模式 | 止盈止损能自动触发；只减仓不会反向开仓 |
| **M6 完善** | 历史页；权益曲线；排行榜；账户重置；压测与故障演练 | 历史分页正常；流水能对上；重置有冷却 |
