## 二、通用规则（所有模块都要守）

1. **数值不用浮点**：接口给的价格、数量、金额全是字符串。展示用 `lib/format/`，要计算就 `parse()` 成 bigint 走 `packages/shared`。`Number()` / `parseFloat` / `toFixed` 不许出现在金额路径上
2. **依赖账户全局状态的数不在前端算**：强平价、保证金率、可用余额、未实现盈亏、ROE 一律用服务端给的值。前端只算两样：下单预估成本、盘口累计量
3. **服务端的错误原样显示**：`ApiError.message` 已经是中文，不翻译、不拼接
4. **算不出来就显示 `--`**：接口给 `null` 的时候，不显示 `0`
5. **实时数据断过线就要重新对齐**：WS 重连、重新登录、页面在后台超过 30 秒，账户数据都要 REST 全量重拉（M00 已实现，后面的模块不要绕过）
6. **行情降级时禁止下单**：`market-store.matchingEnabled === false` 时，所有提交订单、平仓的入口都禁用

### M03 K 线图

用 TradingView Charting Library（`public/charting_library/`，不进 git）。

**功能点**

- [ ] 图表组件只在客户端加载，卸载时销毁
- [ ] Datafeed 适配器（`lib/tv-datafeed.ts`）：

  - `getBars`：`GET /market/klines`，支持往左拖加载更早的数据（`endTime` 翻页，单次最多 1500 根）
  - `subscribeBars` / `unsubscribeBars`：订阅 WS `kline:<SYMBOL>:<interval>`，同一根 K 线更新、收线后开新的一根
- [ ] 切换币对时不销毁图表，调 `setSymbol()`
- [ ] 周期选择记住（`ui-store.klineInterval`，刷新后保留）
- [ ] 主题：背景、网格、涨跌色跟全站 token 一致
- [ ] 图表库文件缺失时给出明确提示（"K 线组件未安装，见 apps/web/README.md"），不白屏

**规则**

- K 线数据不进任何 store，由图表库自己管
- K 线 REST 是服务端代理币安的，有限流；拖动加载要防抖，不要连续发请求

**验收**

- 1m 周期看着新 K 线实时生长，到整分钟收线开新的
- 切 1h、1d 数据正确；往左拖能加载更早的数据

### M07 下单

整个前端逻辑最复杂的模块。

**功能点**

- [ ] 订单类型：限价、市价、止损限价、止损市价、止盈限价、止盈市价
- [ ] 输入：
  - 价格（限价类）：失焦时按 tickSize 向下截到合法值；"最新价"快捷填入；和盘口点击联动
  - 触发价（止盈止损类）+ 触发依据（标记价 / 最新价）
  - 数量：单位可切换"币 / USDT"。按 USDT 输入时换算成币数，按 stepSize 向下取整
  - 百分比滑块：按"可开最大数量"换算
  - 选项：只减仓、生效时间（GTC / IOC / FOK / GTX）
- [ ] **双向持仓模式**：多一个"开仓 / 平仓"切换，`side` 和 `positionSide` 按这张表填，不要自己推：

  | 操作 | side | positionSide |
  | --- | --- | --- |
  | 开多 | BUY | LONG |
  | 平多 | SELL | LONG |
  | 开空 | SELL | SHORT |
  | 平空 | BUY | SHORT |

  单向模式一律 `positionSide: BOTH`
- [ ] **前端即时校验**（只为即时反馈，服务端的校验链才是标准）：价格对齐 tickSize、价格在 minPrice～maxPrice 内、数量对齐 stepSize、不低于 minQty、名义价值不低于 minNotional、市价单数量用 marketMinQty / marketStepSize；价格偏离标记价超过 percentPrice 时给警告但不拦
- [ ] **预估区**（买、卖各一份）：
  - 成本 = 价格 × 数量 ÷ 杠杆 + 预估手续费（前端用 bigint 算）
  - 可开最大 = 服务端可用余额换算，再受当前杠杆所在分层的 notionalCap 限制（缺口 #44）
  - 预估强平价：调 `POST /orders/preview`，输入停止 300ms 后请求
- [ ] **杠杆调整**：1～该币对最高；显示当前杠杆下的最大可开仓位（按分层表）；提交 `POST /positions/leverage`
- [ ] **保证金模式切换**（全仓 / 逐仓）：有持仓或挂单时不能切（`MARGIN_MODE_LOCKED`）；提交 `POST /positions/margin-mode`
- [ ] **提交**：
  - 按钮状态：未登录 → "登录"；行情降级 → 禁用；校验不过 → 禁用 + 原因；提交中 → 禁用
  - `clientOrderId` 前端生成（`c-时间戳-序号`），失败重试用同一个，服务端保证幂等
  - 成功 Toast；失败显示服务端原因
  - 成功后不手动改 store，等 WS `order` 推送

**数据**：`POST /orders`、`POST /positions/leverage`、`POST /positions/margin-mode`、`account-store.account.availableBalance`、`/market/symbols` 的规格和分层表

**后端要补**

1. **`GET /account/symbol-config?symbol=`**：返回这个币对当前的杠杆和保证金模式。现在只有持仓里带这两个值，没持仓时下单面板不知道当前是几倍、全仓还是逐仓（币安对应 `GET /fapi/v1/symbolConfig`）
2. **`POST /orders/preview`**：预估强平价、保证金率、可开最大量（05 第 10 节）。没做之前"预估强平价"显示 `--`

**验收**

- 限价、市价、止盈止损各下一单，当前委托里出现（M08）或直接成交
- 数量低于最小值时按钮禁用并写明原因
- 余额不足时显示服务端的"可用余额不足"
- 连点下单按钮只下一单
- 双向模式下四种开平组合都正确
- 行情降级时按钮禁用

### M08 仓位、委托与账户

**功能点**

- [ ] **仓位表**：币对、方向（多空由 `positionAmt` 正负或 `positionSide` 决定）、数量、开仓均价、标记价、强平价、保证金、未实现盈亏 + ROE；标记价推送时实时更新
- [ ] **平仓**：市价平仓（二次确认，`POST /positions/close`）、限价平仓（下一张只减仓限价单）、一键全部市价平仓（可选）
- [ ] **调整逐仓保证金**：增加 / 减少，显示可调范围；减到会立刻强平时服务端拒（`MARGIN_WOULD_LIQUIDATE`）
- [ ] **止盈止损**：给仓位挂 `TAKE_PROFIT_MARKET` / `STOP_MARKET` + `closePosition: true`
- [ ] **当前委托表**：时间、币对、类型、方向、价格、数量 / 已成交、**前方排队**（`queueAhead`，`queueEstimated` 为 true 时显示 `≈` 和说明）、触发条件、冻结保证金、撤单
- [ ] 全部撤单（按币对，二次确认，`DELETE /orders?symbol=`）
- [ ] 历史委托、成交记录（最近 20 条，"查看全部"跳 `/orders`）
- [ ] "只看当前币对"开关
- [ ] tab 上显示数量：仓位 (2)、当前委托 (3)
- [ ] **账户概览**：保证金率（带风险等级）、维持保证金、保证金余额、钱包余额、未实现盈亏、挂单冻结；`missingMarkPrices` 非空时相关数值显示 `--` 并说明
- [ ] 未登录：整块显示"登录后查看"

**数据**：`account-store`（REST 首屏 + WS `account` / `position` / `order` 推送，M00 已接好）；历史部分走 React Query

**规则**

- 表里所有数值直接用服务端给的，不自己算盈亏和强平价
- 推送来的仓位 `positionAmt = "0"` 表示已平，从表里去掉（store 已处理）
- 撤单成功后不手动删行，等 WS `order` 推送

**验收**

- 下单成交后仓位立刻出现，未实现盈亏随标记价每秒变
- 挂单的"前方排队"随着盘口成交变小
- 撤单、平仓、调保证金都能成功，结果通过推送反映
- 断网 30 秒再恢复，仓位和委托和服务端一致
- 故意开高杠杆等被强平：弹强平通知，仓位消失
