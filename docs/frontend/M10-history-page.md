## 一、这一讲做了什么

`/orders` 页面从占位块变成了真页面：**五个 tab + 两个筛选 + 「加载更多」翻页**。

| tab | 看的是 | 关键的列 |
| --- | --- | --- |
| 历史委托 | 已经结束的单子（成交 / 撤销 / 过期 / 拒绝） | 状态、拒单原因 |
| 成交记录 | 逐笔成交（一张单子可能吃出好几笔） | Maker / Taker、手续费、已实现盈亏 |
| 资金流水 | 钱包余额的每一次变动，8 类 | 金额（带符号）、**变动后余额** |
| 资金费 | 每 8 小时一次的结算 | 费率、名义价值、收 / 付 |
| 强平记录 | 每一次强平 | **强平前保证金 / 维持保证金** |

还在的东西：未登录提示、每个 tab 自己的空状态（带「去交易」）、出错时显示服务端给的中文原因 + 「重试」。

## 二、三个值得说的决定

### 1. 页面状态全写进网址

`/orders?tab=fills&symbol=BTCUSDT` —— 你现在看的是哪个 tab、筛的是哪个币对，都写在地址栏里。

为什么值得单独说：这决定了三件事**能不能用**。

- 刷新页面，还在原来那一屏（不会跳回第一个 tab）
- 浏览器的前进 / 后退能用
- 把链接发给别人，对方打开看到的是同一屏

配套的还有两个小事：网址里写了看不懂的东西（比如 `?tab=nope`，或者一个已经下架的币对）**不报错也不白屏，当成没写**；换 tab 用的是 `replace` 不是 `push`，所以按返回键回到的是你来之前的页面，而不是在五个 tab 之间来回退。

### 2. 翻页用「加载更多」，不做页码

服务端给的是**游标分页**：每次要「从这条往后再来 50 条」，而不是「第 3 页」。

原因在服务端那边（`pagination.ts` 里写着）：成交和流水是一直在长的。用页码的话，你在看第 2 页的时候新成交了一笔，第 3 页的内容会整体往后挪一格——**同一条记录你会看见两次，另一条你永远看不到**。游标不会，因为它记的是"上次看到哪儿了"，不是"数过去第几条"。

所以底部是一个「加载更多」按钮，到底了会写「共 N 条，没有更多了」。

### 3. 已经下架的币对，价格照样显示

这是个小坑。价格显示几位小数，是按币对的"最小变动单位"推的——而这份规格只有**还在开放交易**的币对才有（比如 TONUSDT 已经下架结算了，S01 那次发现的）。

交易页遇到查不到规格的币对，直接不显示那一行。历史记录不能这么干：**那笔交易真实发生过**，不能因为币对下架了就装作没有。所以规格查不到时，按这个数自己带的小数位显示——既不猜精度，也不显示 `--`。

同一条原则的另外两处：
- 市价单没有委托价，价格列显示「市价」，不显示 0
- 没成交过的单子，成交均价显示 `--`，不显示 0（那是"没有"，不是"零元"）

## 三、顺带收掉的两件事

**1. 强平弹窗的「查看详情」接上了**（M01 最后一项）

之前被强平会弹窗，但弹窗里只摆得下这一次的几个数。现在多了个「查看详情」按钮，跳到 `/orders?tab=liquidations`，完整的取证记录在那儿。M01 到此全部做完。

**2. 中文标签统一成一份**

"限价 / 市价 / 止损限价……""已成交 / 已撤销……""全仓 / 逐仓"这些词，原来交易页写一份、历史页再写一份，迟早会出现同一个东西在两个页面叫两个名字。现在收到 `app/_shared/labels.ts` 一份，两边都用它。

> 注意：**服务端返回的错误原因不在这份表里**。那是后端给的中文，原样显示、不翻译——这是 M10 通用规则第 3 条。

## 五、要你验收的（需要登录）

我这边没有可用账号，**表里有没有数据、数字对不对，只有你登录了才能看**。请你过一遍：

1. 登录后打开 `/orders`，五个 tab 分别有没有数据（至少「资金流水」应该有一条"开户赠送"）
2. 有超过 50 条记录的 tab：点「加载更多」，看有没有**重复的行**、有没有**跳过的行**
3. 币对筛选选一个，列表是不是只剩那个币对；资金流水再试一次类型筛选
4. 筛好之后刷新页面，tab 和筛选条件还在不在
5. 下一单、撤一单，回到这个页面看新记录有没有自动出现（不用手动刷新）
