## 一、这一讲做了什么

`/rules` 从一个占位页变成了一篇长文：**左边目录、右边正文**，四节内容——

| 段落 | 讲什么 |
| --- | --- |
| 和真实交易所的差别 | 9 条失真点，每条写「现象 · 为什么这么做 · 对你的影响」 |
| 撮合与排队 | 你的单在哪成交、市价单为什么会被拒、前方排队是怎么估出来的 |
| 保证金、强平与资金费 | 费率、保证金率、强平的四步、资金费什么时候结算 |
| 账户与重置 | 初始资金、「余额等于流水之和」、重置做了什么、对排行榜的影响 |

还接上了界面上的四个 `?`：盘口底部说明、当前委托的「前方排队」、账户的「保证金比率」、行情条的「资金费率」，点一下跳到规则页对应段落。

## 二、三个值得说的决定

### 1. 内容按设计文档写，没按 Figma 稿的文案

设计稿（4:6482）里那几段文案和实际逻辑对不上：强平写成「按标记价市价平仓」（实际是逐档吃盘口 + 破产价兜底）、市价单那段没提吃穿深度会拒单、重置那段没提 24 小时冷却和对排行榜的影响，而且整个缺了「和真实交易所的差别」这一节。

这是你 2026-09-19 定的：**稿子只用样式，内容按设计文档重写**。这次照办了。

### 2. 费率不写死在页面里

手续费率（Maker 0.02% / Taker 0.05%）和清算费率（按币对 1.25% 或 1.5%）这几个数，**是从服务端现取的**，不是抄在页面里的文字。

原因很简单：写死一份，哪天服务端改了费率，规则页会**理直气壮地告诉用户一个错的数**——比不写还糟。现在取不到就显示 `--`。

代价是这一小块得是客户端组件（要发请求），整页其余部分仍然是服务端渲染的静态内容。

### 3. 锚点有测试盯着，不会出现死链接

界面上的 `?` 跳的是 `/rules#queue` 这种带锚点的地址。这类链接有个经典的坏法：**有人改了段落的锚点名字，`?` 还指着老名字，点了跳到页面顶部**——不报错，没人发现，用户只是觉得「这个问号没用」。

所以锚点定义在一份单独的文件里，规则页的段落表拿它当准绳，**有一条测试断言「每个被别处引用的锚点，规则页都必须有对应段落」**。改名字忘了改另一边，测试会红。

## 三、这一页说了些什么（挑几条你可能想核对的）

- **市价单吃穿一半以上可见深度会被拒单**——因为再往下的价格我们不知道，按「最后一档加点滑点」硬成交等于编数字
- **最新价碰到你的挂单价，单子可能还没成交**——价格碰到只说明那个价位有人成交，不等于排在你前面的量被吃完了。真实交易所也是这样
- **强平的四步**：撤挂单 → 逐档吃盘口（比破产价还差的档位不吃）→ 剩下的按破产价平 → 依次扣已实现盈亏、吃单手续费、清算费，每项最多扣到剩余资产为 0
- **不做部分强平**，触发就平掉整个仓位
- **资金费结算时间跟着币安走**，不自己算本地整点；行情断过线、拿不准那一刻的费率时**这一期不结算也不补**
- **重置不是直接改余额**：撤单 → 按标记价平仓 → 补一笔「账户重置」流水，为的是守住「余额等于流水之和」
- **重置会影响排行榜**：统计周期内重置过的账户不进当期日榜、周榜（否则亏完就重置，收益率可以刷）
