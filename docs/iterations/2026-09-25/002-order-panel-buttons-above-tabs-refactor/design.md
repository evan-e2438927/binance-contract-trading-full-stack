## 1. 技术方案概要

### 1.1 概述
交易页下单面板（`OrderPanel` 组件）目前先渲染「订单类型 tab 行」（限价/市价/条件委托），再渲染「杠杆/保证金模式/持仓模式」按钮行。本次把这两个区块的 JSX 顺序互换，按钮行移到 tab 行上方，同步调整两行的上边距 Tailwind 类以保持视觉间距一致。纯前端展示层调整，不涉及状态管理、数据请求或业务逻辑改动。

### 1.2 目标
- 按钮行（杠杆 / 保证金模式 / 持仓模式）渲染在 tab 行（限价 / 市价 / 条件委托）上方
- 两行之间、以及与面板顶部之间的视觉间距与调整前观感一致（不产生贴边或跳跃式留白）
- 按钮/tab 的点击逻辑、禁用态、弹窗行为、双向持仓下的开仓/平仓行零改动

### 1.3 非目标（Scope 外）
- 不改变任何状态管理逻辑（`useOrderFormStore`、`dialog` state、`useAccountStore` 等）
- 不改变按钮/tab 的视觉样式（颜色、圆角、字号、`ConfigButton` 组件本身）
- 不改变双向持仓开仓/平仓行、价格数量输入区、预估信息区、买卖按钮、账户信息区

| 2026-09-25（apply 阶段实现时发现并调整） | tab 行的顶部间距用 `mt-3.5`（margin），而不是设计假设里写的 `pt-3.5`（padding） | tab 行自带 `h-[34px]` 固定高度，项目全局 `box-sizing: border-box`（Tailwind preflight 默认）；若用 `pt-3.5`（14px）会从 34px 的固定高度里扣掉，把 tab 按钮压缩进剩余 20px，导致 tab 文案/`border-b-2` 激活态指示条挤压变形。`mt-3.5` 是外边距，不计入元素自身 `h-[34px]`，能达到同样的视觉间距而不影响 tab 行内部布局。按钮行（现在排第一）保持不带任何顶部间距不变 |
